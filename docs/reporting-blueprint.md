# Reporting Blueprint

This document defines outbound and assessment reporting requirements. It is
documentation-only and does not create dashboards, queries, or schema changes.

## Reporting Sources

Twenty:

- People: ownership, contact data, lead source, lead stage, assessment fields.
- Companies: segment, industry, ICP, operational maturity, owner.
- Tasks: due dates, completion status, assignee.
- Opportunities: stage, owner, amount/value, company, point of contact.
- Notes/timeline: qualitative context after write patterns are validated.

Supabase:

- `assessment_submissions`: source submissions, scoring, sync status.
- `workflow_jobs`: workflow attempts, retries, failures.
- `crm_sync_logs`: CRM operation audit trail.
- `outbound_events`: planned/approved/completed/skipped outbound touch history.

## Metric Definitions

First touch completion rate:

```text
completed first-touch events / planned first-touch events
```

Second touch completion rate:

```text
completed second-touch events / planned second-touch events
```

Connection request acceptance percentage:

```text
accepted connection outcomes / completed connection request touches
```

Response percentage:

```text
leads with response_received event / leads with at least one completed touch
```

Assessment sent percentage:

```text
leads with assessment CTA completed / leads in assessment campaign
```

Assessment completed percentage:

```text
assessment completions / assessment CTA completed
```

Warm lead conversion percentage:

```text
leads entering Warm Assessment Queue / assessment completions
```

Discovery conversion percentage:

```text
discovery requested or scheduled / warm assessment or discovery-ready leads
```

Follow-up completion percentage:

```text
completed due follow-up tasks / due follow-up tasks
```

Stale lead count:

```text
active leads with no next task or overdue next touch past threshold
```

## Data Model Recommendations

Use Supabase `outbound_events` as the source of truth for touch counts and
conversion math. Copy only high-signal summary fields into Twenty when reps need
CRM-native list filtering.

Candidate denormalized fields for CRM list views:

- `outboundPipelineType`
- `cadenceStage`
- `lastOutboundTouchDate`
- `nextOutboundTouchDate`
- `enrichmentStatus`
- `staleRisk`
- `discoveryReadiness`
- `leadHealthScore`
- `icpFitScore`

Avoid using free-text notes as the primary reporting source. Notes are useful for
context, but metrics should come from structured fields and events.

## Lead Source Values

Approved values for reporting:

- `LINKEDIN`
- `EVENT`
- `DROP_IN`
- `REFERRAL`
- `ASSESSMENT`
- `WEBSITE`
- `EMAIL`
- `PHONE`
- `MANUAL`
- `OTHER`

Conversion by source should use these values rather than free-text source labels.
